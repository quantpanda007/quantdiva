For speed and efficiency — split into 3 files. Here's why:
Single file at 3,000 lines — every time you ask me to change a chart function, I need to read through the entire file to find the right spot, risk breaking something in the HTML or CSS while editing JS. Slower iterations, higher error rate.
Split into 3 — you say "fix the ladder chart", I open optima.js, go straight to the function, edit it, done. The HTML never gets touched. The schema never gets touched. Each file has a single concern:

optima.html — structure + CSS (~400 lines, rarely changes)
optima_schema.js — data definitions (~900 lines, changes when you add instruments)
optima.js — all behavior + rendering (~1,500 lines, changes most often)

Maximum split (5 files) — overkill at this stage. Adds complexity without proportional benefit. We can split optima.js further later if it grows beyond 2,500 lines.
Deployment stays identical — FastAPI serves optima.html from /frontend/templates/, the JS files load from /frontend/static/ which you already have mounted.
So the answer: 3-file split. Plotly via CDN for charts. That's the sweet spot.
